# v0.2 Webhook Handlers

This milestone adds webhook ingestion for GitLab and GitHub merged events.

## What was added

- `POST /webhook/gitlab` endpoint
- `POST /webhook/github` endpoint
- Signature/token validation in `internal/webhook/webhook.go`
- Payload parsing and normalization in:
  - `internal/webhook/gitlab.go`
  - `internal/webhook/github.go`
- Shared normalized event type:
  - `internal/webhook.Event`
  - `internal/webhook.Commit`
- Unit tests for signature validation and payload normalization

## Endpoint behavior

Both webhook endpoints now follow the same behavior:

- Return `405` for non-`POST` requests
- Return `401` when signature/token validation fails
- Return `400` for invalid JSON payloads
- Return `200` with `{ "ignored": true, ... }` for events that are not merged MR/PR events
- Return `202` with `{ "accepted": true, ... }` when a merged event is accepted

The server currently logs accepted normalized events and prepares data for the v0.3 generation pipeline.

## Signature validation

- GitLab: compares `X-Gitlab-Token` with `GITLAB_WEBHOOK_SECRET`
- GitHub: validates `X-Hub-Signature-256` (HMAC SHA-256 over raw payload) using `GITHUB_WEBHOOK_SECRET`

If the corresponding secret is empty, validation is skipped to simplify local development.

## Normalized event model

Webhook payloads are normalized into this shared struct:

- Provider (`gitlab` or `github`)
- Repository
- Title
- Author
- Branch
- Description
- Number
- URL
- MergedAt
- Commits

This keeps provider-specific parsing isolated and gives future milestones a consistent input shape.

## How to test quickly

1. Start server:

```bash
go run ./cmd/server
```

2. Call GitLab endpoint with token:

```bash
curl -i -X POST http://localhost:8080/webhook/gitlab \
  -H "Content-Type: application/json" \
  -H "X-Gitlab-Token: your-secret" \
  -d '{"object_kind":"merge_request","project":{"path_with_namespace":"acme/hermes"},"user":{"username":"yuri"},"object_attributes":{"iid":1,"title":"My MR","description":"desc","source_branch":"feature/x","state":"merged","action":"merge","url":"https://gitlab.example/mr/1","merged_at":"2026-04-16T10:30:00Z","last_commit":{"message":"feat: test"}}}'
```

3. For GitHub, generate `X-Hub-Signature-256` from the raw payload and your `GITHUB_WEBHOOK_SECRET`, then send:

```bash
curl -i -X POST http://localhost:8080/webhook/github \
  -H "Content-Type: application/json" \
  -H "X-Hub-Signature-256: sha256=<computed-hmac>" \
  -d '{"action":"closed","repository":{"full_name":"acme/hermes"},"pull_request":{"number":2,"title":"My PR","body":"desc","html_url":"https://github.com/acme/hermes/pull/2","merged":true,"merged_at":"2026-04-16T10:30:00Z","head":{"ref":"feature/x"},"user":{"login":"yuri"}}}'
```
