# v0.3 LLM Integration

This milestone adds a pluggable LLM abstraction and prompt generation pipeline.

## What was added

- `internal/llm/provider.go`
  - `Provider` interface: `Generate(ctx, prompt) (string, error)`
  - `Config` model and provider factory (`New`, `NewFromEnv`)
  - Provider selection by `LLM_PROVIDER` (`openai`, `azure`, `anthropic`)
- Provider implementations:
  - `internal/llm/openai.go`
  - `internal/llm/azure.go`
  - `internal/llm/anthropic.go`
- Prompt builder:
  - `internal/generator/prompt.go` reads and executes `templates/<name>.tmpl`
- Generator orchestrator:
  - `internal/generator/generator.go` builds prompt + calls provider
- Server wiring:
  - `cmd/server/main.go` initializes generator from env and attempts generation when merged webhook events are accepted

## Design notes

- Uses Go standard library only (`net/http`, `encoding/json`, `text/template`)
- Keeps provider-specific HTTP payloads isolated in each provider file
- Keeps generation orchestration in `internal/generator`
- Uses normalized webhook data (`internal/webhook.Event`) as the single input model

## Runtime behavior

- If LLM config is missing, server still starts and webhook ingestion still works
- When merged events arrive:
  - If provider is configured, server generates a release note and logs preview output
  - If provider is not configured, generation is skipped with a clear log message

This lets you test webhooks independently from AI credentials.
